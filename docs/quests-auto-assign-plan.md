# Задания: автовыдача и автопроверка

Статус: **реализовано** (миграции 0011–0015, `backend/routers/quests.py`,
тесты `backend/tests/test_quests.py`).

## Модель

У квеста два независимых предиката, оба — списки условий по view
`user_facts` (AND по списку):

| Назначение | Поля | Смысл |
|---|---|---|
| Выполнение | `complete_conditions jsonb` | NULL — ручная проверка автором; список — квест зачитывается сам, сдать вручную нельзя |
| Выдача | `auto_assign bool`, `assign_conditions jsonb` | `auto_assign` — система выдаёт сама; `[]` — всем, список — подходящим |
| Инфляция | `retro_credit bool` (default true) | `false` — не выдавать тем, кто условие выполнения уже закрыл |

Условие: `{"field": "xp", "op": "gte", "value": 300}`. Операторы — enum
`filled | eq | ne | gte | lte | gt | lt`; `gte/lte/gt/lt` — только для
числовых полей. Валидация на записи (422) и CHECK на форму в БД.

### view `user_facts`

Профиль (`name, email, phone, telegram, title, avatar, role, xp`) плюс
агрегаты по играм без материализации и хуков: `games_played` (одобренные
брони на состоявшиеся игры), `games_mastered` (проведённые игры ГМа). Белый
список полей для условий — столбцы этого view. Новый факт = новый столбец
во view + строка в `ALLOWED_FIELDS`.

## Механика: `sync_auto_quests(user)`

1. Выдать все активные `auto_assign`-квесты, чьи `assign_conditions`
   выполняются, если у юзера **нет никакой записи** по квесту (любой
   статус — выдано, отказ и т.п. не выдаются повторно). При
   `retro_credit=false` — пропустить, если `complete_conditions` уже
   выполнены.
2. Зачесть все взятые квесты с выполненными `complete_conditions`:
   `completed` + XP + аудит.
3. Повторять до неподвижной точки (макс. 5 раундов): XP от зачёта может
   открыть квест с условием `xp >= N`, который тут же зачтётся.

Вставка — `INSERT … ON CONFLICT (quest_id, user_id) DO NOTHING`:
параллельные вызовы (несколько логинов) безопасны, проверено тестом.

### Точки вызова — только изменения состояния

Регистрация, логин, `PATCH /auth/me`, загрузка аватара, смена роли/титула
админом, зачёт ручного квеста (начисление XP), взятие автоквеста с доски.
**На чтениях (`GET /me`, `GET /quests`) sync не вызывается** — никакой записи
при чтении.

Раздача при появлении нового автоквеста — обязанность системы, а не
«когда зайдут»: `POST /quests` с `auto_assign` ставит фоновую задачу
`sync_everyone` после коммита; `POST /quests/{id}/sync` (админ) — повторная
раздача вручную, возвращает число новых выдач.

## Инварианты в БД (миграция 0015)

- `complete_conditions` / `assign_conditions` — NULL или JSON-массив (CHECK)
- `auto_assign` несовместим с `assignee_id` (CHECK)
- `app_users.xp >= 0` (CHECK)
- `UNIQUE (quest_id, user_id)` на assignments (с 0011)
- JSONB-колонки в ORM объявлены `none_as_null=True` — Python `None`
  пишется как SQL NULL, а не JSON `null` (это ловил CHECK)

## Правила (осознанные решения)

- **Инфляция XP принята**: по умолчанию выполнивший условие раньше получает
  зачёт при выдаче. Автор квеста отключает это `retro_credit=false`, тогда
  такие игроки квест не получают вовсе (невыполнимый «поменяй телефон» не
  выдаётся).
- Выданное не отзывается, если критерий перестал выполняться.
- Неактивный квест не выдаётся; уже выданные остаются.
- Зачёт необратим и одноразовый.
- Автовыдача игнорирует `max_takers`.
